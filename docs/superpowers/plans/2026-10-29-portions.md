# 份量算准 + 滑杆 实现计划

> 设计：`specs/2026-10-25-on-time-checkin-design.md` 第三块「份量算准」，改动一处：点一道菜改份量不用 `wx.showActionSheet`，
> 改成抽屉（`components/sheet`）里一根滑杆（`components/slider`，`specs/2026-10-27-ui-controls-design.md` 的「联动滑杆」）。

**目标**：小暖按克数估每道菜、程序加总；结果页点一道菜，用滑杆拖到她实际吃的量，热量跟着变；改过的记下来，下次估同一样菜时参考。

## 定下来的做法

- **AI 给每道菜**：`name`、`portion`（一碗）、`grams`（吃下去的克数）、`kcal`、`protein`、`carbs`、`fat`；不再要总数（给了也只在没有菜时用）。
- **parse**：`grams` 0～3000 取整（0 = 没给）、`kcal` 0～5000 取整、营养素 0～500 一位小数（三样都给了才记在这道菜上）；
  总热量 = 每道菜之和（菜的热量全是 0 时退回 AI 的总数）；营养素每道菜都有才按菜加总，不然用 AI 的总数。
- **`meal.adjust { mealId, index, grams? | factor? | remove? }`**：
  - 只能改分析好、是食物的打卡；`index` 越界、`grams` 不在 1～3000、`factor` 不在 0.1～5 → `BAD_REQUEST`。
  - 有克数的菜用 `grams`（也认 `factor`，换算成克数）；老打卡没克数的菜只能 `factor` / `remove`。
  - 这道菜的热量、营养素按比例缩放；**总数按这道菜的变化量加减**（老打卡的总数不一定等于菜之和，不动别的菜的那部分）；
    这道菜没有营养素时，总营养素按总热量的比例缩放。
  - 只剩一道菜时不能删（「这顿就剩这一道了，没吃的话删掉整条打卡吧」）。
  - 第一次改把 AI 原来的存进 `analysis.aiFoods` / `aiTotalKcal`，`analysis.adjusted = true`，改过的菜 `adjusted: true`；评级、点评、暖豆都不动。
  - 改了克数（不是删）就记进集合 `portions`（`_id = openid`）`items: { 米饭: { grams, at } }`，留最近 12 样。
- **提示词**：「按碗、盘、筷子的大小估克数；她家常用份量（下面有的话）优先」；
  `【她家常用份量】她自己改过的：米饭一般吃约 110 克；白粥一般吃约 250 克。同样的菜照片看不清份量时按这个估`（最近 8 样，同名才算）。
  记的是「她一般吃多少」，不是「一碗多少克」：她把一碗拖成半碗，可能是碗小，也可能只吃了一半，这样说两种都对。
- **滑杆**（`components/slider`）：轨道、填充、圆钮、数值跟手（`slider.wxs` 在渲染层改 transform，不每帧 setData），
  数值按 `step` 跳了才 `callMethod` 一次（气泡里的字、页面的「约 N 千卡」）；按住圆钮放大、上面冒数值气泡；点轨道直接跳过去；
  页面改 `value`（快捷按钮）时带一点过渡滑过去。事件：`changing`（拖的时候，数变了才发）、`change`（松手）。
- **结果页**：每道菜「米饭 · 约 150 克 · 174 千卡 ›」，点了弹抽屉「米饭吃了多少？」：大字「约 150 克 · 174 千卡」、滑杆、
  快捷「一半 / 少一点 / 原样 / 多一点 / 两倍」、「这道没吃」、「就这么多」。没克数的菜滑杆是「原来的 ×1.5」。
  改过的显示「份量按你说的改过（小暖原来估 640 千卡）」。
- **打卡页**：拍照框下面四条小贴士（斜上方 45° / 菜都拍进去 / 旁边放双筷子或勺子 / 吃之前拍）。
