# 小岛花园 · 大世界 — 设计文档

日期：2026-10-23 · 状态：待确认 · 取代：[小岛后花园](2026-10-23-island-garden-design.md) 的 12×12 方岛、四个角落、花坛、程序画的底图和篱笆遮罩；保留其中的首页布局（左上资源条、左右圆按钮、底部大打卡按钮）

## 目标

参照用户发来的游戏截图：花园要像精品手游的主城一样，是**一整张画出来的场景**，而不是一块平草地上贴物件。

- 岛比一屏大得多（约 3 屏宽、2 屏多高），形状自然，路弯弯曲曲；拖着屏幕逛，一路发现荷塘、喷泉、温泉……
- 场景按「白模 → 即梦重绘 → 对齐格子」做：我用程序搭白模（地形、路、小溪、建筑位置都对准格子），用户用即梦照着白模画成整张原画
- 10 个区域：2 个一开始就有，8 个花暖豆修整；没修的盖云雾，修好云雾散开
- 扭蛋物件、小动物仍是单独的图，摆在场景上，脚下加阴影；小动物沿着路走到各处去玩

## 世界

### 坐标

- 世界大小 1050 × 1400（1 倍缩放时 = 屏幕 px），整张原画按 3:4 铺满它
- 背后是一张等距格子网：每格宽 44、高 22；格子 (c, r) 的顶点在 (525 + (c − r) × 22, (c + r) × 11)。c、r ∈ [0, 76)，画面上看不出格子
- 每格有两样属性：**属于哪个区域**（或不属于任何区域：海、悬崖）和**是什么地**：
  - `lawn` 空草地：能摆东西、小动物能走
  - `path` 石板路、广场、桥：小动物能走，不能摆
  - `decor` 画好的花草树木、绿篱、菜畦：只是景色，不能摆也不能走
  - `block` 建筑、山石、水面、风景：不能摆也不能走
- 格子表由脚本按白模的形状算出来，生成到 `lib/shared/world-map.js`（云函数和小程序共用）；原画到了以后按画面微调形状、重新生成

- 全部修好共 3200 暖豆
- **挨着已修好的地方才能修**（按路连着算）：中心花园连着小院、动物小院、荷塘、花圃、果园、竹林；动物小院 → 菜园；荷塘 → 温泉；花圃或菜园 → 喷泉广场
- 每个区域都有几块空草地（`lawn`）能摆东西；中心花园最大
- 秋千古树、水车画在区域之间，只是景色
- 熊猫一家仍要 3 丛翠竹：竹林画了 2 丛，第三丛要自己摆

### 修整

- 没修的区域盖着一团团云朵；挨着已修区域的，路口立木牌「修整荷塘水榭 · 200 暖豆」，点了确认；不挨着的只有云，没有木牌
- 修好：云朵往外飘散淡出，冒金色彩带，区域露出来
- 文案：暖豆不够「暖豆不够啦，修整要 X 暖豆，再攒攒」；不挨着「要先修好旁边的地方」；已修好「这里已经修整好了」；不存在「没有这个地方」

### 不能摆的原因

「放不到花园外面哦」（海、悬崖）、「这里还没修整呢」、「小路上不能摆东西」、「这里种着花草，换块空草地吧」（`decor`）、「这里已经有风景了」（`block` 和风景）、「这块地上已经有东西了」

### 新手礼与旧数据

- 第一次进花园：送 60 暖豆，在中心花园草坪靠后的一格种大树
- 旧数据（12×12 小岛、3×3 大地图、更早的小庭院，文档里没有 `world: 3`）：已摆的东西全部收回背包，大树重新种好；以前修整角落、开荒花的暖豆全部退回；只开小院和中心花园。写回 `world: 3`

## 画面

### 原画和占位

- 原画（即梦出的 3:4 大图）切成 3 × 4 块放云存储，页面按块铺；原画没到之前，用白模（同样切块）当底图
- 页面背景是原画四周海的颜色，拖到岛外也不穿帮
- 删掉程序画的岛、篱笆遮罩、花坛和岛边花草

### 云雾

- 每个没修的区域：按它的格子范围铺 5～9 朵云（大小、位置有一点随机但固定），慢慢飘动
- 先用程序画的柔和云朵占位，即梦的云到了换上

### 摆在场景上的东西

- 扭蛋物件、小动物脚下加一圈半透明的椭圆阴影
- 风景（荷塘、竹子等）在原画里，格子上只记一个看不见的「风景点」：挡路、算小动物喜欢的东西、小动物去那里玩（游泳、啃竹子、趴着打盹）

### 浏览

- 缩放 0.45～1.5 倍；第一次进来停在中心花园和小院；左下「🏠」回到中心花园
- 摆放模式只亮起已修区域里的空草地

## 架构

| 位置 | 改动 |
|---|---|
| `scripts/world/`（新） | `shapes.py` 区域、路、小溪、建筑、草地的形状（世界坐标）；`blockout.py` 画白模；`build_map.py` 按形状算格子表，生成 `world-map.js`；`cut_art.py` 把原画（或白模）对齐、切块、压缩，输出到 `art/world/` |
| `lib/shared/world-map.js`（新，生成） | `GRID`、`TILE`、`ORIGIN`、`AREAS`（id、名字、价格、相邻、木牌位置、云朵范围）、`ROWS`（每格区域和地的种类）、`SPOTS`（风景点）、`STARTER_TILE` |
| `lib/shared/garden.js` | 去掉 12×12 小岛的 `REGIONS`、`SCENERY`、`regionOf` 等；新增 `areaOf`、`tileKind`、`canUnlock(opened, id)`、`spotsIn(opened)`、`walkable(opened, c, r)`、`placeProblem(opened, placed, c, r, ignoreUid)` |
| `lib/garden-state.js` | `opened` 默认 `['home', 'center']`；`world: 3` 迁移 |
| `services/garden.js` | `view` 的 `regions` 改为 `areas: [{ id, name, cost, unlocked, unlockable }]`，`scenery` 改为风景点；`unlock` 加相邻校验；`arrive` 算上风景点 |
| `scripts/wechat.js` | 新命令 `npm run wx:art`：把 `art/world/` 的切块传到云存储 `garden/world/` |
| `utils/world.js` | 换成大世界：`worldLayout()`、`centerOffset`、`artTiles()`（底图切块位置）、`cloudViews(areas)`、`signViews(areas)`、`tileFromTouch`、`placeChecker`、`walkChecker` |
| `utils/garden-life.js` | 能走的格子由 `walk(c, r)` 决定；风景点当物件 |
| `utils/garden-view.js` | 物件带阴影数据；风景点不出图 |
| `pages/garden` | 底图切块、云朵、木牌、阴影；去掉花坛、岛边、海浪；缩放范围 |

## 测试

- 格子表：每个区域有空草地和木牌；风景点在 `block` 格上且旁边有能走的格子；全部修好时每块能走的格子都能从中心花园走到；相邻关系双向；新手大树在中心花园的空草地上
- shared：`placeProblem` 各种原因、`canUnlock`、`walkable`
- service：修整（扣豆、不挨着、已修、豆不够）、风景点引来小动物、旧数据迁移（三种旧格式）
- 端到端：修好荷塘 → 打卡 → 仙鹤或小黄鸭搬来
- `world.js`：布局、底图切块、云朵和木牌只在该出现的地方、点按换算（拖动缩放后）
- `garden-life`：只走路和草地、会去风景点玩
- 页面：首页流程、摆放的各种拒绝、修整（不挨着时没有木牌）、回到中心

## 不做（YAGNI）

多张原画拼接、区域内风景随修整阶段变化、昼夜和天气、小动物进屋、点建筑进去有功能。
