# 准时打卡放第一位 — 设计文档

日期：2026-10-25 · 状态：已确认（五块逐块确认过）

## 背景与目标

小程序的本意是「替家人监督减肥」：每顿饭拍照给养生师看，算清楚吃了多少。营地小游戏做了很多，但用户（妈妈的孩子）明确了优先级：
**准时拍照打卡第一，热量要算对；小游戏第二。**

现状的问题：

- 没有「饭点」：早饭晚上补拍也一样算，印章、暖豆都一样，准时没有任何好处。
- 没有提醒：妈妈不打开小程序就不会被提醒（最早的设计把「饭点提醒」「家人查看」放在第二期，一直没做）。
- 份量估不准（用户实际碰到的问题）：AI 看一眼给个数，估得不准只能写一句话让 AI 重看；总热量用的是 AI 自己报的总数，可能和每道菜加起来对不上。
- 首页是营地小游戏，打卡入口在营地右下角和「今日」页。

成功标准：

- 打开小程序第一眼就知道「下一顿是什么、几点前拍算准时、拍了没有」，一个大按钮直接去拍。
- 饭点到了手机会响；快过饭点还没拍，妈妈收到微信提醒；过了饭点还没拍，家人收到通知。
- 准时拍的比补拍的明显划算（印章金色、暖豆多），补拍也照样记热量、不批评。
- 每道菜按克数显示，加起来一定等于总数；份量不对点一下就能改，改过的份量下次 AI 会参考。
- 家人在自己微信里能看到妈妈每顿拍没拍、吃了什么，能点赞。

## 已确认的决策

| 项 | 决定 |
|---|---|
| 首页 | 换成「今日」打卡页，营地挪到第二个 tab（今日 · 营地 · 体重 · 我的） |
| 准时规则 | 妈妈设三个饭点，饭点前后 1 小时内（含）拍算准时；过点能补拍，热量照记，印章普通、暖豆少 |
| 提醒 | 两种都用：手机日历重复闹钟（每天饭点响）+ 微信服务通知（快过饭点还没拍才发） |
| 份量 | AI 按克数估每道菜，程序加总；点一道菜就能改份量；记住她家常用份量喂给 AI |
| 家人 | 能看 + 点赞 + 漏拍通知：妈妈邀请，家人在自己微信里看，过饭点没拍通知家人 |
| 连续天数 | 不做「连续准时」（一断就泄气），用「本月准时 N 顿」（只增不减）+ 日历上的金色印章 |
| 上线顺序 | ① 首页 + 准时 → ② 提醒 → ③ 算准 → ④ 家人；每块做完发预览。② 等用户的模板 ID，没到就先做 ③ |

## 一、首页和准时

### 饭点

- 档案加 `mealTimes: { breakfast: 'HH:MM', lunch, dinner }`，默认 `07:30 / 12:00 / 18:00`，建档页和「我的」里改，半小时一档。
- 校验：分钟只能是 00 / 30；早饭 05:00～10:00、午饭 10:30～14:00、晚饭 16:00～21:00；相邻两顿至少隔 2 小时（窗口不重叠）。
  这样所有窗口都落在 04:00～22:00 之间，不会跨午夜。
- 老档案没有 `mealTimes` 就按默认（`mealTimesOf(profile)`）。

### 准时判定（新的共用模块 `shared/timing.js`，两边逐字节一致）

- 窗口 = 饭点 ± 60 分钟（含两端）。按东八区本地时间算。
- 打卡提交那一刻定 `timing`：`'on'`（窗口内）/ `'early'`（窗口前）/ `'late'`（窗口后）；加餐是 `null`。
- `timing` 写在这条打卡上（`meals.timing`），之后改饭点不影响过去；重新分析不改 `timing`。
- 同一天同一顿拍了几次：只要有一次 `'on'`，这顿就算准时。评级仍按最新一条（沿用现有规则）。
- 上线前的老打卡没有 `timing`，一律算不准时（普通印章），已经得的暖豆不动。
- 模块提供：`DEFAULT_MEAL_TIMES`、`WINDOW_MINUTES`、`mealTimesOf`、`validateMealTimes`、`windowOf(mealType, times)`、
  `timingFor(mealType, at, times)`、`mealStatus(meals, times, now)`（首页大卡的状态，见下）。

### 暖豆（取代现在按「拍了几顿」分档的 `STAGE_BEANS`）

| 条目 | 暖豆 |
|---|---|
| 每顿正餐准时拍 | +15 |
| 每顿正餐不在饭点拍（早或晚） | +5 |
| 三顿都准时 | 另加 +15 |
| 每顿评级「吃得好」（绿） | +5 |
| 一天最多 | 75（以前 60） |

- 新函数 `dayBeans(meals)` 返回 `{ beans, meals: { breakfast: { logged, onTime, rating } … }, allOnTime }`；`syncDay`、日历、今日卡片、打卡结果页的「得了多少」都改用它。
- 加餐照旧不算暖豆。扭蛋 30 一抽、商店价格不变。
- 提示文案改成围绕准时：「午饭 11:00～13:00 拍算准时，能得 15 暖豆」「三顿都准时再加 15」「过点了，现在补拍也有 5 暖豆」。

### 首页（`pages/today`，tab 第一个）

从上到下：

1. **下一顿大卡**（`mealStatus` 算出来，页面显示时每分钟刷新一次）：
   - 窗口前：「午饭 · 12:00」「11:00～13:00 拍算准时」+ 大按钮「📷 拍午饭」
   - 窗口中：同上 +「还剩 40 分钟」
   - 拍过了：「午饭准时拍了 ✓」（不准时就是「午饭拍了 ✓」），下面一行「下一顿：晚饭 18:00」
   - 过点没拍：橙色「午饭还没拍，现在补拍也算数」+ 按钮「📷 补拍午饭」，不批评
   - 三顿都拍完：「今天三顿都拍完啦」+ 小按钮「加餐也可以拍」
   - 选哪一顿（按顺序，取第一条成立的）：
     1. 现在正在某顿的窗口里：拍了 →「拍过了」，没拍 →「窗口中」
     2. 某顿刚过点不到 2 小时、还没拍 →「过点没拍」
     3. 之后还有没拍的 → 最近的那顿「窗口前」
     4. 今天还有过了点没拍的 → 最晚的那顿「过点没拍」
     5. 都拍了 →「拍完」
2. **印章行**：早 / 午 / 晚，准时 = 金色描边 + 角上一个「准」字，不准时 = 普通评级颜色，没拍 = 空心；旁边「本月准时 23 顿」。
3. 现有的热量进度、今天各餐、今日总结（不变；「📷 拍一拍这一餐」按钮并进大卡）。

- 按钮带着餐次去打卡页（`/pages/checkin/checkin?mealType=lunch`），打卡页按它预选，也能改。
- 打卡页餐次下面显示「现在拍午饭：准时 ✓」或「现在不在午饭时间，补拍也算数」。
- 打卡结果页的暖豆横幅说清楚：「午饭准时打卡 +15 暖豆」「三顿都准时，再加 15！」。
- 日历页（`pages/forest`）的印章同样分金色 / 普通，月统计加「准时 N 顿」。
- 「本月准时 N 顿」：`day.get` 多查一次本月的打卡（`listMealsBetween(月初, 今天)`），按天算准时的正餐数加总。
- 没建档仍然先去建档；第二块做好以后，建档成功会接着进一次「饭点提醒」设置页。

### 小暖的点评带上准时

- 提示词加一行：`【拍照时间】12:10，准时（午饭饭点 12:00）` 或 `【拍照时间】15:20，不在饭点（午饭饭点 12:00）`。
- 要求：准时的顺口夸一句；不准时的温和提醒「下顿按时吃、吃之前拍」，不批评；点评字数限制不变。

### 营地

- 挪到第二个 tab，其余不变：营地里的拍照按钮保留，正餐打卡后照样回营地庆祝。

## 二、提醒

### 设置页（新页面 `pages/remind/remind`「饭点提醒」）

从「我的」进入；第一次建档成功后自动进一次。最好家人陪妈妈一起设一次。内容：

- 三个饭点（显示，点了去档案改）。
- **手机闹钟**：按钮「在手机日历里加三个饭点闹钟」。
- **微信提醒**：开关「快过饭点还没拍，用微信提醒我」+「还能提醒 N 次」+ 一句说明（见下）。

### ① 手机日历重复闹钟

- 一次点击里依次调三次 `wx.addPhoneRepeatCalendar`（基础库 2.15.0+，`scope.addPhoneCalendar` 授权）：
  - `title`：「小暖提醒：拍午饭（11:00～13:00 准时）」
  - `startTime`：下一个午饭饭点（秒），`alarm: true`，`alarmOffset: 0`（饭点那一刻响），`repeatInterval: 'day'`
  - `description`：「打开微信 → 小暖养生 → 拍午饭。准时拍能得 15 暖豆」
- 成功后记下加的时间和当时的饭点（`remind.calendarDone`）：页面显示「已加好（7:30 / 12:00 / 18:00）」。
- 小程序只能加、不能删日历：饭点改过以后页面提示「手机日历里还有旧闹钟，要在日历里手动删掉，再点一次加新的」。
- `wx.canIUse('addPhoneRepeatCalendar')` 为假：提示「微信版本太旧，升级微信后再加」。拒绝授权：提示并给「去设置里打开」（`wx.openSetting`）。

### ② 微信服务通知（一次性订阅消息）

- **模板**：用户在小程序后台「订阅消息 → 公共模板库」选一个「打卡提醒 / 用餐提醒」类模板，把模板 ID 给我。
  写进云函数配置 `config.remindTemplate = { id, state: 'trial', fields: { … } }`：`fields` 把我们的三段文字映射到模板的字段名（`thing1`、`time2`……，选定模板后按它的字段填）。
  `id` 为空时整个服务通知功能隐藏，只剩日历闹钟。家人的漏拍通知用同一个模板。
- **次数**：微信规定每「允许」一次只能发一条。做法：
  - 每次点「交给小暖看看」提交打卡时，在点击里先调一次 `wx.requestSubscribeMessage`（必须在点击的同步调用里），回调后再上传；
  - 设置页的开关也调一次；
  - 第一次弹窗时让妈妈勾「总是保持以上选择，不再询问」再点「允许」，之后不再弹，每次打卡都悄悄攒一次；
  - 结果是 `accept` 就调 `remind.subscribed`，次数 +1（上限 30）。
  - `wx.getSetting({ withSubscriptions: true })` 查到这个模板被设成拒绝时，设置页提示「微信里关掉了提醒」并给「去设置里打开」。
- **什么时候发**：饭点 + 30 分钟起、窗口结束前，这顿还没拍（任何时间拍的都算拍了）、今天这顿还没发过、次数 > 0 → 发一条，次数 −1：
  - 内容（按模板字段）：「午饭还没拍哦」「午饭 12:00」「13:00 前拍还算准时」；点开进首页。
  - 每顿每天最多一条。
- **定时触发器**：`api` 云函数加 timer 触发器 `remind`，每 10 分钟一次（`0 */10 * * * * *`）。
  - `config.json`：`permissions.openapi` 加 `subscribeMessage.send`，`triggers` 写上这个触发器（开发者工具上传时用）；
  - `scripts/wechat.js` 加 `trigger` 命令（`npm run wx:trigger`），用 miniprogram-ci 的 `cloud.createTimeTrigger` 从云端创建。
  - `index.js`：`event.Type === 'Timer'` 时不走路由（没有 OPENID），调 `remind.tick(now)`。
- **发送失败**：`43101`（没有次数 / 用户拒收）→ 次数清零、这顿记为已发（不再重试）；其他错误写日志、不记已发（下个 10 分钟再试，窗口结束就停）。

### 数据和接口

- 集合 `reminders`：`_id = openid`，`notify`（是否开微信提醒），`credits`，`sent: { 'YYYY-MM-DD': { lunch: 时间戳 } }`（只留最近 7 天），
  `calendar: { at, times }`。次数是「这个人 + 这个模板」的，家人收通知也扣他自己的这份。
- actions：`remind.get`（模板 ID、开关、次数、日历记录、饭点）、`remind.subscribed { accepted }`、`remind.setNotify { on }`、`remind.calendarDone { times }`。
- 纯函数 `planReminders({ times, meals, now, sent })` → 这一刻该提醒的餐次（在 `lib/remind.js`，单测覆盖）。

## 三、份量算准

### ① 拍之前：打卡页的拍照小贴士

照片框下面几行大字：从斜上方拍（约 45 度）、所有菜都拍进去、旁边放一双筷子或勺子当参照、吃之前拍。

### ② AI 按克数估，程序加总

- 提示词：每道菜给 `name`、`portion`（口语份量，如「一碗」）、`grams`（估计吃下去的克数）、`kcal`、`protein`、`carbs`、`fat`；不再要总数。
  估算要求加：「按碗、盘、筷子的大小估克数；她家常用份量（下面）优先」。
- `parse.js`：每道菜 `grams` 0～3000 取整、`kcal` 0～5000 取整、三大营养素 0～500 保留一位；
  **总热量 = 每道菜热量之和**，三大营养素也按菜加总（某道菜缺营养素时退回用 AI 给的总数）；没有菜（纯文字一句话）才用 AI 的总数。
- 结果页每道菜显示「米饭 · 约 150 克 · 174 千卡」。

### ③ 点一道菜改份量

- 结果页点一道菜 → `wx.showActionSheet`：只吃了一半 / 比这少一点 / 比这多一点 / 是这个的两倍 / 填准确克数 / 这道没吃
  （系数 0.5 / 0.75 / 1.25 / 2，填克数用 `wx.showModal` 的输入框，「没吃」删掉这道菜）。
- action `meal.adjust { mealId, index, factor? | grams? | remove? }`：
  - 只能改已完成、是食物的打卡；`index` 越界、系数不在列表里、克数不在 1～3000 → `BAD_REQUEST`。
  - 这道菜的热量和营养素按新旧克数的比例缩放（老打卡没有克数：只能用系数或删除）；重算总数。
  - 第一次改时把 AI 原来的菜单存进 `analysis.aiFoods`；`analysis.adjusted = true`。评级、点评不变，暖豆不受影响。
- 结果页显示「份量按你说的改过（小暖原来估 640 千卡）」。补漏掉的菜仍用现有的「补充描述后重新分析」。

### ④ 记住她家的常用份量

- 改了某道菜的克数（不是删掉）就记下：集合 `portions`（`_id = openid`）`items: { 米饭: { grams: 110, at } }`，留最近 12 样。
- 下次分析，提示词加：`【她家常用份量】米饭一碗约 110 克；白粥一碗约 250 克（她自己改过的，同样的碗按这个估）`，最多 8 样。
- 同名才算同一样（AI 叫法不一致时它自己会对上，不做模糊匹配）。

## 四、家人

### 邀请和加入

- 妈妈：「我的」→「家人」→「邀请家人一起看」（`button open-type="share"`）转发给家人；进这一块时先拿一个邀请码（`family.invite`，7 天有效，没过期就复用）。
  分享卡片：标题「妈妈邀请你一起看她每天的养生打卡」，路径 `/pages/family/join?code=XXXXXX`。
- 家人点卡片（用自己的微信身份）→ `pages/family/join`：「{妈妈的昵称} 邀请你一起看她每天的打卡」，选关系（女儿 / 儿子 / 老伴 / 其他）、写称呼 → 「加入」。
  已经加过直接进家人页；自己不能加自己；码过期提示「邀请过期了，请妈妈再发一次」。
- 妈妈那边列出已加入的家人，可以移除；家人也可以「不看了」。家人只能看，不能改任何东西。

### 家人看到什么（`pages/family/family`）

- 「妈妈今天」：下一顿大卡的状态（同首页，只读）、早 / 午 / 晚印章（金色 / 普通）、每顿的照片 / 菜 / 热量 / 评级 / 小暖点评、今天吃了多少对预算、本月准时 N 顿。
- 能看前几天（前一天 / 后一天）。
- 每顿一个 👍：点了妈妈那边这顿显示「❤️ 小鱼 赞了」（首页卡片和结果页）。同一个人对同一顿只算一次。
- 漏拍通知开关 +「还能通知你 N 次」；点 👍 和开关时都悄悄申请一次订阅（同第二块的办法）。
- 进入方式：家人自己没建档 → 打开小程序时（今日页发现没档案、但有关注的人）直接 `reLaunch` 到家人页，页面底部「我也想自己打卡 → 建档」；
  家人自己也在用 → 首页顶部一张「看看妈妈今天 ›」卡片。关注了不止一个人时页面顶部切换。

### 漏拍通知

- 同一个定时任务：饭点 + 60 分钟（窗口结束）起的一小时内，妈妈这顿还没拍、这条家人关系今天这顿没发过、家人的次数 > 0 → 发给家人：
  「妈妈的午饭还没拍」「午饭 12:00」「去微信问问她吧」；点开进家人页。每顿每天每个家人最多一条。
- 纯函数 `planFamilyAlerts({ times, meals, now, sent })`，单测覆盖。

### 数据和接口

- 集合 `invites`：`_id = 邀请码`（6 位，去掉易混字符），`owner`、`ownerName`、`createdAt`、`expiresAt`。
- 集合 `family`：`_id = viewer_owner`，`owner`、`viewer`、`name`、`relation`、`notify`（默认开）、`sent: { 'YYYY-MM-DD': { lunch: 时间戳 } }`、`createdAt`。
- `meals.likes: [{ viewer, name, at }]`。
- actions：`family.invite`、`family.preview { code }`、`family.join { code, name, relation }`、`family.list`（我的家人 + 我关注的人）、
  `family.remove { viewer }`、`family.leave { owner }`、`family.day { owner, date? }`、`family.like { owner, mealId }`、`family.setNotify { owner, on }`。
- 权限：所有 `family.*` 在云函数里先查关系，没关系一律 `NOT_FOUND`「没有找到这位家人」；`family.day` 只返回只读字段，
  照片用云函数 `getTempFileURL` 换成临时链接（妈妈的照片对家人的小程序不可直读）。
- `day.get` 多返回 `following: [{ owner, ownerName }]`，今日页用它决定没档案时去建档还是去家人页。

## 五、上线、测试、出错

### 上线顺序

1. **首页 + 准时**：`shared/timing.js`、档案饭点、`meals.timing`、新暖豆规则、首页大卡和印章、打卡页预选和准时提示、日历金色印章、点评带准时、tab 顺序。共用文件改了要重新部署云函数。
2. **提醒**：设置页、日历闹钟、订阅次数、定时触发器、发送。需要用户先选模板给 ID；没到就先做 3。
3. **算准**：提示词按克数、解析加总、结果页改份量、`meal.adjust`、常用份量、拍照小贴士。
4. **家人**：邀请 / 加入、家人页、点赞、漏拍通知。

每块：`npm test` 全绿 → 部署云函数（共用文件或云函数改了）→ `npm run wx:preview` 发二维码。
实现计划按这四块分别写（`docs/superpowers/plans/`），一块做完、用户试过再写下一块。

### 测试

- `timing`：窗口两端（含）、早 / 晚、加餐、东八区跨日、饭点校验（范围、30 分钟一档、间隔 2 小时）、老档案默认值、`mealStatus` 各种状态。
- 暖豆：准时 / 不准时 / 三顿准时加成 / 绿色加成 / 同一顿多次拍取任一准时 / 老打卡没有 `timing`。
- 提醒：`planReminders` 和 `planFamilyAlerts`（窗口内外、拍了不发、发过不发、次数为 0 不发）、`remind.tick`（成功扣次数、43101 清零、其他错误不记已发）、
  `remind.subscribed` 上限、timer 事件在 `index.js` 不走路由。
- 份量：`parse` 每道菜加总、缺营养素退回、钳制；`meal.adjust` 各选项、越界、老打卡没克数；常用份量的记录和提示词。
- 家人：邀请过期、自己加自己、重复加入、没关系看不到 / 点不了赞、点赞去重、照片换临时链接、移除后看不到。
- 页面（`page-harness`）：首页大卡各状态和按钮去向、没档案时去建档 / 去家人页、打卡页预选、结果页改份量、设置页、家人页。
- 端到端（`fake-cloud`）：打卡 → `timing` → 暖豆；`meal.adjust`；邀请 → 加入 → 家人看 → 点赞 → 妈妈看到。
- 每块真机扫码看。

### 出错和边界

- 日历接口不可用 / 拒绝授权：提示升级微信或去设置打开，不影响其他功能。
- 订阅被拒 / 次数用完：设置页和家人页显示次数为 0 和「去打开」。
- 模板 ID 没配：服务通知相关的开关都不显示，日历闹钟照常。
- 定时任务出错只写日志，不影响打卡。
- 改饭点：只影响以后的打卡和提醒；日历里的旧闹钟要手动删（页面提示）。

## 不做（YAGNI）

- 连续准时天数、补签卡、准时排行榜。
- 拍吃前 / 吃后两张照片算吃了多少。
- 本地菜品热量库、菜名模糊匹配。
- 家人给妈妈发文字消息（家人直接用微信说就行）、家人改妈妈的记录。
- 长期订阅消息（个人小程序的类目用不了）。
