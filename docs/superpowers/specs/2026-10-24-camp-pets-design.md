# 暖暖营地 — 设计文档

日期：2026-10-24 · 状态：已确认 · 取代：[园林大宅院](2026-10-23-garden-estate-design.md)（格子、围墙、修院子、物件扭蛋）和 [庭院小动物](2026-10-23-garden-animals-design.md)（真实动物、摆物件引来）；修改：[庭院扭蛋](2026-10-23-garden-gacha-design.md)（扭蛋机保留，池子从物件换成食物）；保留首页布局（左上资源条、左右圆按钮、底部大打卡按钮）、打卡和 AI 点评、暖豆和早午晚印章

## 为什么重来

宅院版有三个问题，两个是结构性的，修修补补治不了：

1. **自由摆在格子上，东西永远是「贴」上去的**。物件单独画成透明图再放到一张大画上，接地、影子、色调靠每张图自己对，树看起来浮在草地上；桥能放草地、荷花池能摆菜地，和场景不搭。
2. **有围墙就有穿模**。小动物走到墙边、穿门洞，靠从底图抠块遮挡只能减轻，减不到零。
3. 小动物是「真实动物」，没有记忆点，交互少。

参考宝可梦 Sleep：它好看不是因为视角，而是（1）东西都在设计好的位子上、（2）宠物姿势多、（3）画得精。所以：

- **一块开阔的营地**，镜头高一点，没有墙、没有门，宠物走到哪都挡不住。一张图做到极致。
- **装饰「原地重绘、整块替换」**：每件装饰都让 Codex 在营地原图上画出来，连一圈草地一起裁下来，边缘羽化，放到草地任何位置都接得上。
- **宠物是原创小精灵**，每只一个「动物 × 养生食材」的记忆点，交互动作多；食物引它来，打卡喂熟。
- 暖豆只花两处：扭蛋抽食物、商店买装饰。没有解锁、没有云雾。

## 营地

### 画

- 一张**正方形**的大草坪，高清版约 4096×4096（Codex 先出 1024×1024，再切 16 块逐块重绘拼成高清版）。切 4×4 共 16 块传云存储，页面按块拼。它比手机屏幕大一圈：默认只看到中间一半宽，像 Pokémon Sleep 那样拖着看两边。
- 镜头 45～50 度俯视（比宅院的 30 度高），柔和的白天光线。画风是**手绘 2D 插画**（软、暖、圆润、无黑描边），**不是 3D 渲染**——Codex 放开画会往 3D 跑，所以每张图都带 `art/guide/style-camp.jpg` 当画风参考（2026-10-24 用户定的）。
- 画里的**基础设施一开始全在**，没有解锁：正中一堆篝火，火上三脚架吊着一口大陶锅「暖暖锅」（营地的中心，对应 Pokémon Sleep 的卡比兽）；大帐篷在草坪的**最左上角**（远离锅、门朝篝火，默认视角看不到，拖过去才看到；没窝的宠物在门口睡）；篝火右下两个食盆。其余是**一整片空旷、均匀的草坪**，草坪里不放树、不放水面、不放木台。树林只在画面上缘当背景（宠物从那里走进来），远处是山。（2026-10-24 用户看了 Codex 几版初稿后定的：小溪多此一举；草坪里的树也不要；场地要像 Pokémon Sleep 那样比一屏大；中心放一口锅而不是一只大家伙；帐篷放锅后面太怪，最后定在最左上角、锅居中偏前。）
- **帐篷和锅是抠出来的独立一层**（`SCENE.cutouts`：box + 落地的 zy）：页面把 `images/camp/cut/tent.png`、`pot-N.png` 叠在底图上，按 zy 排 z，宠物走到后面就被挡住、走到前面就盖在上面。Codex 出「去掉帐篷 / 去掉锅」两版，`cutouts.py` 比对得到范围。
- **暖暖锅**：早上是空锅、**火也没点**（锅底下是一堆冷柴，没有火苗、火光、火星；夜里火边也只有月光）；今天打了第一顿正餐火才点起来，每打一顿锅里就多一层（早：粥底，午：加菜，晚：满锅冒热气），两顿起冒热气。页面按今天早午晚印章里有状态的数量（0～3）换锅的抠图 `pot-0～3.png`（`camp-view.potLevel/cutoutViews`）。傍晚宠物围着的就是这口锅。以后可以做连续打卡换大锅、火边加水壶之类的成长。
- **草地要均匀、少杂物**：这是装饰块能放在任何位置的前提，工单里定死。
- 默认视角和全景：营地画是正方形，竖着的手机屏要放下整幅宽度，上下得有差不多两倍高的内容，所以画的上面补了天空、下面补了草地（`SCENE.frame` 各 2048，`scripts/camp/extend_art.py`），**整个世界就是 movable-view 本身、四周不留白**。1 倍是默认视角：营地画的高度是屏幕高度的 0.72 倍（锅占屏幕宽度四成多，2026-10-25 用户嫌以前铺满高度时篝火太大），篝火横着在正中；双指捏小到 `minScale` 是全景（整幅宽度正好放进屏幕，上下是天空和草地），捏大到 `maxScale`（和以前最大一样细）；`out-of-bounds` false，**任何时候都看不到边**。
- **一天的光**：6～17 点日景；17～19 点傍晚在日景上叠一层橙；19～6 点**整套换成夜景图**（Codex 以日景为底画的同构图夜景，切块 `night-t*.jpg`，帐篷 / 锅的抠图也有夜版 `night-*.png`；占位由 `blockout.py` 的夜调色板画），再加萤火虫。

### 坐标

- 全部用画的像素坐标，以 4096×4096 的高清版为准（记作 W×H），不再有格子。页面按当前缩放换算成屏幕像素。
- `shared/camp.js` 里的 `SCENE`：
  - `grass`：草地多边形（能走、能放装饰），一个大多边形减去下面的禁区
  - `nogo`：不能走也不能放的区域，各一个多边形：大帐篷的地面占位、篝火圈
  - `fire`：篝火中心；`cutouts`：帐篷、锅的抠图范围和落地 y；`seats`：围着锅的 12 个坐点（开口朝后的马蹄形，傍晚全员围坐）
  - `bowls`：两个食盆的位置
  - `tent`：大帐篷门口 3 个睡觉点（帐篷地面占位在 `nogo.tent`）；`sun`：篝火右边向阳草地上 3 个晒太阳点
  - `entries`：树林边缘的 3 个入口（新住户从这里走进来，鹤鹤从这里飞走）
  - `shade`：树林边上 4 个树荫睡觉点
- **远近缩放**：`scaleAt(y) = 0.82 + 0.18 × y / H`。画面最下面 1.0，最上面 0.82。装饰块和宠物都按脚下的 y 缩放。
- **前后顺序**：谁的脚（y）在下面谁画在前面。宠物、装饰块都按 y 排 z-index，互相不会穿。

## 装饰

### 做法：原地重绘、整块替换

- 每件装饰都是在营地原图的一块草地上由 Codex 画出来的，然后**连周围一圈草地一起裁下来**，边缘 24px 羽化成透明。因为草地均匀，这块放到草地上任何位置都接得上，影子、接地、光线都是画里的。
- 每件装饰记：`patch`（块的宽高，高清版像素）、`foot`（落脚框：块里真正占地的矩形，用来判断重叠，默认块的 60%）、`anchor`（脚底中点在块里的位置）、`spots`（宠物在它上面能坐 / 睡 / 玩的点和动作）、`fx`（自带的小动效）。
- 块按 `scaleAt(y)` 缩放后贴到营地上，z 按 anchor 的 y。

### 规矩（能不能放）

`placeProblem(placed, decorId, x, y, ignoreUid)` 返回不能放的原因（能放返回 `''`），云函数校验和页面提示用同一套话：

| 情况 | 提示 |
|---|---|
| 落脚框不完全在草地多边形里 | 只能放在草地上 |
| 落脚框碰到大帐篷、篝火圈 | 这儿放不下，挪开一点 |
| 落脚框和别的装饰的落脚框重叠（各外扩 16px） | 和别的东西挤着了 |
| 没有这件装饰 / 没买 | 放不到这里哦 |

## 宠物

### 名单（动物 × 养生食材）

12 只原创小精灵：圆滚滚、大眼睛、小短手，宝可梦那种比例但都是自己的造型。每只的记忆点是一样养生食材长在身上。名字叠字。

- 鹤鹤只在 5～9 点出现在营地（从树林边飞进来，9 点飞走），其余时间图册里写「清晨才见得到它」。它的「走」那一行画的是飞。
- **引来只认同档的食物**：食物的档和宠物的档一样才引得来它，所以鹤鹤只有山楂引得来，莲子只能喂它（+3）。其余 11 只的两样食物都和自己同档。
- 开局豆豆就住在营地里（新手礼的一部分，它头上那颗就是暖豆）。

### 引来

- 扭蛋抽到的食物放进食盆（两个）。放食物时云函数就随机定下来这份食物引谁（爱吃它、同档、还没住进来的里随机一只，存在 `peeking[bowl]`），它会在树林边**探头张望**（页面上出现它的剪影和一个「？」气泡），告诉你有戏；没人可引就不张望。
- 下次**正餐打卡**（早 / 午 / 晚任一顿拿到印章）后，云函数结算 `arrive`：按食盆 1、食盆 2 的顺序，哪个食盆有张望的宠物，它就走进营地（从树林边的入口走到食盆，吃掉食物，加入住户），**一次打卡只来一只**，另一份留着下次。
- 要是爱吃它的都已经住下了，这份食物就由一只爱吃它的住户吃掉（+3 亲密），食盆空出来，页面提示「笋宝把竹笋吃了，营地里没有别的小动物爱吃它啦」。
- 来了的宠物在打卡结果页出横幅（「有新住户！笋宝闻着竹笋来了」），回营地先看到它走进来的动画。

### 喂熟（亲密度）

- 每次正餐打卡，所有住户都算吃了一顿：`fed +1`（三顿，所以打卡这条一天最多 +3；直接喂不限次）。
- 从背包把食物拖到某一只身上直接喂：它爱吃的 `+3`，不爱吃的 `+1`（吃一口就不吃了，有专门的嫌弃动画）。节气点心谁都爱吃 `+5`。
- 五级按 `fed` 算：1 级 0、2 级 3、3 级 8、4 级 15、5 级 25。每升一级：
  - 2 级：解锁睡姿 B
  - 3 级：解锁小动作（伸懒腰、东张西望）
  - 4 级：点它会蹭过来；解锁早上叼礼物
  - 5 级：解锁专属动作；图册这页的小故事写完
  - 每级图册里多一句它的小故事（5 句，设计时一并写进 `PETS`）。

### 一天的作息（按手机本地时间）

| 时段 | 做什么 |
|---|---|
| 5～8 早 | 在食盆和篝火附近晃，打卡后吃饭；4 级以上的某一只叼礼物过来 |
| 8～17 白天 | 在草地上溜达；去玩自己喜欢的装饰（秋千、滚球、木梯、滑梯）；橘团、龟龟去篝火右边的向阳草地晒太阳；累了随便找个地方坐 |
| 17～19 傍晚 | **全员围着篝火坐**（12 个坐点），偶尔换个姿势、互相蹭蹭 |
| 19～5 夜 | 睡觉：优先去窝（帐篷、吊床、树洞、草窝、金帐篷，按买的先后），没窝的去树荫，树荫满了睡大帐篷门口；睡姿 A / B 轮换；偶尔翻身 |

- 鹤鹤例外：5～9 点出现，其余时间不在。

### 走动

- 草地是一整块多边形，想去哪就直线走过去；目标点随机选在草地里、离别的宠物一个身位以上；走的时候碰到禁区（小溪、水塘、木台、树干）就绕一个点。速度每秒约 90 像素（高清版坐标，按缩放换算）。
- 走路用侧面行走帧，左右镜像；往上走、往下走也用侧面（镜头高，看不出）。
- 到了目标做一件事（坐、玩装饰、晒太阳、泡水、吃），停 4～12 秒，再选下一个。

### 交互（每种都是一段动画）

| 手势 | 反应 |
|---|---|
| 点一下 | 抬头看你，说一句话（台词按性格和时段，每只 8 句以上） |
| 连点两下（400ms 内） | 咯咯笑、打滚 |
| 长按（≥500ms） | 摸摸：眯眼冒爱心，发出呼噜（震动一下） |
| 从背包把食物拖到它身上 | 直接喂，吃的动画，亲密度按上面的规则加 |
| 早上第一次打开（当天 5 点后第一次进营地） | 4 级以上的住户里随机一只叼着礼物走到画面中间，点一下收下：5 暖豆（70%）或一份普通食物（30%）。一天一次，没有 4 级住户就没有 |
| 打卡成功后回营地 | 全员跑到篝火边蹦一蹦（3 秒），有新住户的话接着播它走进来 |

### 它们之间（白天随机触发，每次一对）

## 画面融合：动的东西怎么和画长在一起

营地是 Codex 画的一整张手绘图，没有现成的分层素材，所以「融合」靠一套固定的分层和规矩，每一条都从画本身取数，画换了重跑脚本就行。

**分层（从下到上）**

| 层 | 是什么 | 从哪来 |
|---|---|---|
| 垫图 | 整个世界（营地画 + 上下补的天空、草地）的 768 宽低清版，包里自带 | `extend_art.py`；一打开就有画，高清块下完盖上；块之间缩放时露的细缝透出来的也是同一张画 |
| 底图 | 日 / 夜整图各 16 块（3072 / 2048） | `cut_art.py` → 云存储 |
| 上下补的天空、草地 | 天空两行、草地两行各 4 块；草地第一行多盖住画最下面 160 像素（生成时发虚的那段被新草换掉）。草地是从画上的草一块块拼的（Efros-Freeman：挑和拼好的边最像的块、沿误差最小的曲线接缝，日夜同一套块），天空是画顶那一行往上接的渐变 + 被切掉的云长出圆顶 + 几朵云 / 星星 | `extend_art.py` → 云存储 |
| 熄火补丁（锅是空的时） | 日景火堆那一块、夜景被火照亮的一大圈，换成火熄了的样子；不透明 JPG，框落在切块的像素格上，盖上去没接缝 | `fire_off.py` |
| 火苗（锅里有东西时） | 锅底下那块的 8 帧，帧是从画上的火苗像素做明暗变化来的 | `fx_art.py` |
| 抠图层 | 帐篷、锅连三脚架、木盖、提灯，**物件本身的精确轮廓** | `cutouts.py --from-base` |
| 宠物、装饰、食盆 | 按脚下的 y 排前后 | 页面 |
| 光 | 火光（一闪一闪）、帐篷灯、灯笼光晕，`screen` 叠在所有东西上 | `scene-fx.js`，z 1650 |
| 色调 | 傍晚的橙 | z 1700 |

**抠图**：`cutouts.py --from-base` 在高清日景上，`poly` 只圈个大概，圈里按颜色去掉「像草的」（G 占比高、比 R/B 都大一截）和树林深处的暗青，再从物件身上几个种子点长出连着的那一大块（草里的花、碎叶断开就丢了），边缘按「像草的程度」留半透明、往里收一像素。夜景构图和日景一样，直接用日景的轮廓。输出 WebP，分辨率和底图切块一样、框是 4 的倍数，盖上去像素对齐。以前抠图带着草，宠物走到锅后面就被「假草」盖住，这是根上的修法。不再需要 Codex 画「去掉帐篷 / 锅」的版本。

**前后**：一律按脚下的 y（`zOf`）。三个补充：
- 帐篷斜着放，前沿是折线（`cutouts.tent.front`）：页面把帐篷竖着切成 128 宽的条，每条按自己那段前沿最靠上的点排；禁区比前沿再往外一点，站得到的地方都排对（门口睡觉的点盖在门帘上面）。
- 走路是一段段 CSS 过渡，z 在一段开始时就变：一段路要是跨过某样东西（抠图层的条、装饰、食盆）的那条线、这一段上身子又有哪儿横着挨得到它（不只是跨线那一下，斜着走的后半段挨上也算），就在跨线那一点切开，每小段按中点排。走到锅后面那一刻才被锅挡住，不会提前钻进去，也不会走到提灯后面还盖在提灯上。
- 在装饰上玩、睡（吊床、窝、梯子）的宠物排在那件装饰前面，盖在它上面。
- 停下来的地方（歇着、坐着、睡觉、晒太阳）避开锅身、提灯正后面会被整个挡住的地方（`SCENE.hide`）；早上「火边」只去锅的前面和两边。路过可以。

**绕路**：障碍 = 所有禁区（帐篷连身后、篝火圈、木盖、提灯）+ 摆着的装饰的落脚框。在每个障碍外 60 像素一圈取点，两点直线不碰障碍就连，Dijkstra 最短路；装饰变了才重算。正好穿过多边形顶点的线段也算碰到（以前竖直穿过椭圆上下两个顶点会漏判）。

**光**：`light_map.py` 拿夜景 ÷ 日景的亮度比和夜景偏红 / 偏蓝，算成 32×32 的格子（`utils/camp-light.js`；火没点时用熄了火的夜景另算的一套）。夜里每只宠物、每件装饰两层：本体按那格的亮度压暗或提亮、火边偏暖；上面再盖一层「月光版」（同一张图去色、染成画上夜色那种蓝白），越冷越浓，火边是 0。两层都随位置连续变，走路时和位置用同一个时长过渡。食盆里的食物只调本体。火光、灯光层盖在宠物上面，走到火边的宠物也跟着闪。

**火没点**（锅是空的）：画上的火是画死的，`fire_off.py` 从画上把它熄掉。日景：锅底下木柴之间的黄白色火苗换成柴堆里的暗处，被火苗挡住的木柴按量好的轴线（`LOGS`）顺着补全，柴缝里暗、低处一点灰；火照在木柴、石头、锅底上的暖光按「亮的 = 本色 ×（1 + 衰减 × 火光色）」除掉。夜景：在火、提灯、帐篷都照不到的地方拟合「日景 → 夜景」的颜色变换（草地一套、物件一套），拿熄了火的日景算出只有月光的样子，换掉火照亮的那一大圈（照着夜景比月光预测亮多少算范围），提灯自己那圈光留着。空锅 `pot-0`、夜里的木盖 `night-lid-off`、碗沿 `night-bowl-N-off` 都从熄了火的画上抠；光的格子另算一套 `_OFF`，夜里火没点时宠物、装饰、食盆里的食物按它上色（火边和远处一样冷、盖月光层）。以后 Codex 画了正式的「没点火」版就用它换掉程序熄的。

**镜头**：movable-view 的 x / y 是缩放后**整个世界**的左上角在屏幕上的位置（营地画在世界里往下挪了 `frame.top`，`focusOffset` 换算）。同一次 setData 里既改 `scale-value` 又改 x / y，组件会吞掉一个，所以「回到篝火」「找它」放大过就先缩回 1 倍、等缩完（550ms）再平移；没放大就直接平移。第一次进来排好版后再对准一次篝火（个别机型刚建出来时不认初始 x / y）。

**动效只从画上取**：火苗是画上的火苗在动；锅里的粥画在量出来的真实锅口里；热气是很淡的半透明一缕；食盆里的吃的画在碗口里，碗沿从画上抠下来盖在上面。不在画上用 CSS「画东西」（CSS 画的火团、烟团、蝴蝶和手绘的画放一起很假）。

**怎么验**：单测模拟一整天（8 个随机种子 × 早中晚夜，几只宠物、装饰、庆祝、送礼物），每走一小段沿路取点：只要那一点身子挨着某样东西，前后就必须和这一小段排的一致；路不穿禁区、停的地方看得见；光、火星、萤火虫这些层不挡点击；抠图里像草的像素比例（现在都是 0%）；夜里的光火边亮暖、远处暗冷。再用真实页面逻辑驱动浏览器录屏（`scripts/preview/record-camp.js`），逐帧看宠物从锅后面、木盖旁、提灯旁、帐篷门口经过。
